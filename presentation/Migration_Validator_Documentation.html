1. Executive Overview

1.1 Purpose & Objectives

The Migration Validator is an enterprise-grade data validation framework designed to ensure data integrity during database migrations. It provides automated comparison between source and target databases, leveraging AI for intelligent column mapping and SQL generation.

💡 Why Migration Validator? Traditional migration validation requires manual SQL writing and comparison logic. Migration Validator automates this process using AI, ensuring consistent, auditable, and reproducible validation results.

Primary Objectives

  • Data Integrity Assurance: Verify that all migrated data matches source data exactly
  • Automated Column Mapping: AI-powered matching of source to target columns with transformation rules
  • Coverage Transparency: Clear reporting of what was validated vs. excluded
  • Multi-Database Support: Support for PostgreSQL, MSSQL, Athena, and Snowflake
  • Bi-Directional Analysis: Detect columns in target that don't exist in source

1.2 Key Features

Feature Description Benefit
🤖 AI-Powered Mapping Automatic column matching using GPT-4o Eliminates manual mapping errors
📊 Count Validation Row count comparison between source/target Quick data loss detection
🔍 Data Validation Row-by-row comparison with normalization Detailed mismatch identification
📈 Coverage Metrics Percentage of columns validated Prevents false confidence
🔄 Bi-Directional Analysis Detects target-only columns Schema drift awareness
📝 Exclusion Tracking Documents why columns were skipped Audit trail for compliance

4.2 Running Validations

Using Python API

from src.validation.validation_executor import ValidationExecutor

executor = ValidationExecutor(base_dir=".")
results = executor.execute_batch(
    layer="bronze",
    tables=["all"],
    validation_types=["count_validation", "data_validation"],
    config_dir="config",
)

Validation Types

Count Validation

Compares row counts between source and target:

Source Count: 1,234,567
Target Count: 1,234,567
Result: PASS ✓

Data Validation

Performs row-by-row comparison with normalization:

  • Identifies primary keys
  • Normalizes data types (NULL handling, whitespace, dates)
  • Detects missing rows in either side
  • Generates mismatch CSV report

5. Troubleshooting

Problem: "DIAL_API_KEY is not set"

Error Message: AISQLGenerationError: DIAL_API_KEY is not set

Solution: Set DIAL_API_KEY in your .env file and ensure VPN access to the DIAL endpoint.

Problem: "AI could not produce valid SQL after 3 attempts"

Cause: The model produced SQL that failed dialect validation three times.

Solutions:

  • Exclude exotic column types in config/exclusions.yaml
  • Try with a stronger model: --model gpt-4o

Problem: Snowflake Connection Failure

Common Cause: Using dot format instead of hyphen format for account name.

Solution: Use ORG-ACCOUNT format (e.g., ZJAUJWQ-EP12783), not ORG.ACCOUNT.

Problem: LOW COVERAGE Warning

!! LOW COVERAGE — under 80.0% of columns were compared

Action: Review the excluded columns in the plan JSON and confirm each exclusion is intentional.

Problem: MSSQL Pre-Login Failure

Checklist:

  • Microsoft ODBC Driver 18 is installed
  • Host and port are reachable
  • SRC_2_AUTH matches your authentication type
  • Server supports the configured encryption mode

Problem: UnicodeEncodeError on Windows

Solution:

$env:PYTHONIOENCODING = "utf-8"
